# Iota Trades identity prototype

Experimental and excluded from the base build. Install only in disposable test worlds. See the [five-level design](../../../docs/discovery/drafts/trading_design_directions.md) and [native evidence summary](../../../docs/release_checklist.md#automated-research-evidence--2026-11-20).

This slice assigns a persistent identity when a loaded villager has a profession, gives zero-XP professionals one bootstrap XP to lock their career through vanilla rules, names unnamed villagers at Apprentice and snapshots native offer state. Identity tags support rehydrating the scoreboard after curing changes the entity UUID. Existing custom names and native offers are preserved.

Ordinary villagers receive only the identity behavior. The opt-in catalog probes also exercise offers, stock and commercial XP. The bootstrap point must be subtracted from custom commercial progression. This prototype does not prevent command edits or implement arbitrary mod compatibility. Item naming is en-US. No dependency is required.

## Bounded exact-event experiment

IDs 1 through 64 have dedicated hidden interaction/trade advancements. They identify the actual native target without nearest-villager guessing. This is a bounded research channel, not an approved 64-villager product limit. Higher IDs keep identity behavior but have no exact-event recording in this prototype. Do not ship this capacity boundary or claim an unlimited full Trades runtime.

Exact trade events now record positive native-XP deltas separately by player UUID and resident ID. Two-player native GUI tests credit 3 XP to each actor; a zero-delta replay adds no XP. Interaction establishes the native baseline, so the bootstrap point is excluded. External XP edits during an open trade, unsupported event IDs and final commercial progression still require a production policy.


## Current catalog probes

Run `node tools/build-trading-catalog.mjs` and `node tools/build-trading-runtime-probe.mjs` before loading the pack in a disposable Java 1.21.11 world. Tag a supported villager with `iota_trades_current_probe` before its first catalog initialization to select a test plan from its current catalog. The 132 plans cover all thirteen professions, including separate Librarian plans for each villager type and both Mason specialties. The Cartographer locates map destinations at initialization, excludes earlier destinations and keeps a map slot pending if none can be found. The Journeyman slot can use its approved Spyglass alternative. The villager draws once when its job-site memory is available. The plan is stored by resident ID.

The current draws include equipment purchases. They require full durability. Plain contracts require unenchanted equipment, and optional Basic contracts also accept equipment with at least one approved Basic enchantment at level I or II, with additional effects at the same payout. The [native equipment test](../../../docs/discovery/tests/native-current-equipment-trades.mjs) verifies eight transactions or rejections, including preservation of rejected items. The test also covers a second player attempting to open the same occupied villager, recalculation of a stale marker after an inventory update with the menu open, and a dropped item picked up by the second player. The suite verifies two simultaneous menus at different villagers, with an accepted axe and rejected shears accounted independently in the native offers. Equipment already carrying other values in the components reserved for qualification remains intact and is rejected by this prototype. Compatibility for otherwise eligible items with such components remains open. Unknown offer capacities use one use in the test draws. The fixture has no regional trade layer. IDs 1–64 use the exact event ledger. Higher IDs in the current probe check active offers every tick near players or one tick after departure, and stagger idle checks over a 20-tick period. They only compare individual offers when the native list changed. They do not attribute XP to individual players.

The Toolsmith probe completed a sale of 48 Flint for 12 emeralds, recorded one use and one point of commercial XP, and promoted after the player moved away. The timed refill required the workstation. A second native probe initialized all twelve supported professions at Novice, injected the Master XP threshold, verified their expected offer counts and confirmed that reload kept each plan. The Librarian used its Swamp templates, and the Mason stored its specialty.
The [native Cartographer test](../../../docs/discovery/tests/native-cartographer-plan.mjs) checks that filled maps have IDs and destination markers, persist on reload and omit pending slots in a dimension with no eligible locations. The resolver persists its queue and searches at most one candidate per server tick globally. The native test checks that the same maps survive restock and that a workstation from a different profession does not replenish the Cartographer. One native locate operation can still stall a tick. The first staged run logged a 2.16-second server delay. Measure cold terrain and multiple simultaneous initializations before enabling by default.

The [high-resident native test](../../../docs/discovery/tests/native-trading-high-resident.mjs) verifies two simultaneous trades above ID 64, stock reset correction and a timed refill isolated to one villager. Large-village cost and changes between ticks still need measurement.

The [64-resident benchmark](../../../docs/discovery/tests/benchmark-trading-poll.mjs) used loaded, stationary Master Toolsmiths and one local protocol client on an isolated server. Median tick time with the initial high-ID read path was 91.9 ms (40.1 ms with the same villagers unmanaged). After avoiding repeated identity scans and checking native offers selectively, it was 31.3 ms with the player away and 39.8 ms with the player near the group, against 16.4 ms unmanaged. Five tick-query samples per condition. Terrain search and active transactions across the whole population were outside this benchmark.


## Java 1.21.11 test ZIP

Run `pwsh -File tools/build-trading-test.ps1` to build the separate test ZIP. It compiles individual offer pools for runtime draws across the thirteen approved professions, with the legacy fixed plans and regional assets omitted. Use `/function iota_trades:production/test_spawn` to create a new test villager and give it the desired workstation. Only villagers created or explicitly tagged for this test receive the new catalogs. The standalone ZIP does not enroll naturally born or cured villagers automatically.

The current restock timing and metal quotes are provisional. The next iteration covers restock behavior, Cartographer search performance and price review.
The shipped ZIP is ready to install. Rebuilding and running the native test scripts requires the locally generated Java 1.21.11 registry reports in vendor/generated. For native tests, set IOTA_TEST_RCON_PASSWORD to the password of the disposable local test server.
